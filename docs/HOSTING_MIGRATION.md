# Перенос Jump Higher на новый хостинг

Этот чек-лист рассчитан на перенос Docker Compose-инсталляции без включения
платежей, подписки Pro и бесплатных недельных квот.

## 1. Зафиксировать исходное состояние

- Записать текущий commit SHA и сохранить копию production-конфигурации вне Git.
- Проверить `docker compose ps` и последние логи `api`, `bot`, `worker`.
- Остановить приём новых анализов на время финальной синхронизации.
- Создать зашифрованную резервную копию PostgreSQL и проверить, что дамп читается.
- Сохранить только необходимые Docker volumes. Исходные видео при политике
  `KEEP_SOURCE_VIDEO_DAYS=0` переносить не требуется.
- Не копировать пароли, токены, приватные ключи, `.env` или дампы через GitHub.

## 2. Подготовить новый сервер

Минимальная стартовая конфигурация MVP: 4 vCPU, 6 ГБ RAM и NVMe. Начинать с
одного Celery worker (`--concurrency=1`), пока нагрузочный тест не подтвердит
безопасность второго процесса.

- Обновить ОС и установить Docker Engine с Compose plugin.
- Создать отдельного пользователя развёртывания с `sudo`.
- Разрешить SSH только по ключам; отключить вход root по паролю после проверки.
- Открыть входящие `22/tcp`, `80/tcp`, `443/tcp`.
- Не публиковать PostgreSQL `5432`, Redis `6379` и внутренний API `8000`.
- Настроить синхронизацию времени и автоматические security-обновления.

## 3. Развернуть приложение

1. Клонировать репозиторий и перейти на проверенный commit или release tag.
2. Создать `.env` непосредственно на сервере с правами `600`.
3. Сгенерировать новые уникальные `SECRET_KEY`, `API_KEY` и пароль PostgreSQL.
4. Добавить актуальный Telegram bot token, не выводя его в терминальные логи.
5. Сохранить отключённые квоты и платежи:

   ```env
   FREE_QUOTA_ENABLED=false
   KEEP_SOURCE_VIDEO_DAYS=0
   POSE_BACKEND=rtmpose
   POSE_TRACKING_ROI_ENABLED=true
   POSE_CAMERA_STABILIZATION_ENABLED=true
   TELEGRAM_INIT_DATA_TTL_SECONDS=3600
   ```

6. Собрать образы: `docker compose build`.
7. Восстановить PostgreSQL до запуска пользовательского трафика.
8. Запустить: `docker compose up -d`.
9. Проверить миграции, healthchecks и отсутствие циклических перезапусков.

## 4. HTTPS и Mini App

- Разместить Nginx, Caddy или другой TLS reverse proxy перед FastAPI.
- Проксировать `/miniapp/` и `/miniapp/api/` на `127.0.0.1:8000`.
- Не проксировать PostgreSQL и Redis.
- Выпустить сертификат для нового домена и включить автоматическое обновление.
- Проверить `https://<домен>/health` и `https://<домен>/miniapp/`.
- Только после проверки заменить URL Mini App через BotFather
  (`/setmenubutton` или Bot Settings → Menu Button).

## 5. Приёмочные проверки

- Команда `/start` отвечает в Telegram.
- Одиночное видео проходит загрузку, очередь и анализ.
- Рост запрашивается для каждой попытки и не сохраняется в профиле.
- Mini App принимает настоящий Telegram `initData`; запрос без него получает `401`.
- История показывает только попытки текущего пользователя.
- В карточке отображаются confidence, предупреждения и ограничение 2D-оценки.
- RTMPose-модель уже находится в образе и не скачивается при запуске worker.
- Один тестовый анализ укладывается в Celery time limit.
- После анализа исходное видео удаляется согласно политике хранения.

## 6. Переключение и откат

- Уменьшить DNS TTL заранее, затем переключить домен на новый сервер.
- Старый сервер оставить выключенным для записи, но доступным для отката до
  завершения приёмки и проверки резервной копии.
- При ошибке вернуть DNS и BotFather URL на предыдущий проверенный адрес.
- Не запускать одновременно два бота с polling и одним Telegram token.
- После успешного переноса отозвать неиспользуемые доступы и удалить старые
  незашифрованные копии данных.
